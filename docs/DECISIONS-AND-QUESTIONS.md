# Решения и открытые вопросы

## Приоритет следующей итерации

- Решение пользователя от 18 ноября 2026 года: перед подключением новых агентов заняться переходом из компактной карточки задачи в соответствующий чат.
- Область: Windows и macOS; сначала проверить отдельно для Codex и Claude Code, можно ли надёжно открыть конкретную сессию и какие ограничения действуют.
- После выпуска текущих исправлений разработка приостановлена до следующего поручения пользователя.

## Наведение на окно и точки задач в macOS

- Решение пользователя от 18 ноября 2026 года: при наведении на видимую область окна активировать монитор. Над точками переключения задач в компактном режиме системный указатель должен показывать руку.
- Это решение заменяет прежние варианты с активацией только при наведении на точку и без автоматической активации. Переход фокуса при наведении на окно прямо разрешён пользователем.

## Обнаружение Codex и ChatGPT Work — проверка 23 ноября 2026 года

- Пользователь сообщил, что работающий чат не появился в мониторе; ранее задачи отображались. Связь показанного чата ChatGPT Work с конкретной локальной сессией Codex не подтверждена.
- В опубликованных версиях Windows 0.2.7-alpha, 0.2.8, 0.2.11 и 0.2.12 поиск индексированной задачи выбирает исходный журнал и пропускает формат журнала с дополнительным идентификатором после изменения истории. На локальном примере старый журнал содержит прерванный ход, а актуальный журнал продолжает обновляться. Исправление включено в Windows 0.2.13 и проверено на изолированных примерах.
- Начало текущего локального чата не найдено в последних 16 МиБ журнала, тогда как существующий поиск начала ограничен 8 МиБ. Это отдельная причина, по которой родительская карточка может не появиться при запуске монитора во время долгого хода. В контрольном снимке добавлено ограниченное фоновое наблюдение новых событий; оно не является подтверждением активности.
- На показанном пользователем экране видны две дочерние карточки одной родительской задачи. Подпись из названия родительской задачи и имени агента соответствует ранее выбранному пользователем формату; состояние каждой карточки указано как неподтверждённое.
- Решение пользователя: объединять помощников с родительской задачей в одной карточке и указывать число агентов в скобках. Когда их состояние не подтверждено, показывать число без утверждения, что все они работают, с пометкой о неподтверждённом состоянии. Решение заменяет отдельные карточки помощников для одной связанной задачи; связь необходимо проверять по идентификаторам, а не по совпадению названий. Применить в Windows и macOS.
- Решение пользователя: в полном окне внутри объединённой карточки раскрывать список помощников и их актуальных действий.
- Уточнение пользователя от 24 ноября 2026 года: в компактном окне показывать в скобках число всех запущенных связанных помощников без их имён и списка действий. Увеличивать счётчик при подтверждённом запуске и уменьшать только после подтверждённого выхода помощника из задачи; временная неизвестность не должна уменьшать число. Отдельных помощников скрывать только при подтверждённой идентификации; не угадывать её по названию. Применить в Windows и macOS.
- Запрос пользователя: сделать переключение задач по точкам независимым от обновления данных. Чтение источников и диагностика в текущей версии Windows выполняют синхронную работу на потоке окна; состояние источников и поздние ответы требуют безопасного разделения. Аналогичную проверку выполнить для macOS. До проверки при заблокированном чтении нельзя считать отклик подтверждённым.
- На изолированном примере Windows PowerShell 5 фоновый runspace не удерживал интерфейс при ожидании, но удерживал процесс после окончания скрипта не менее восьми секунд. Этот способ не внедрён. Для безопасного переноса необходимо отдельно проверить жизненный цикл фонового сборщика, сохранение состояния источников и отбрасывание устаревших ответов; не останавливать работающие источники или записи принудительно без доказанной безопасности.
- Прототип отдельного процесса чтения Windows проверен на синтетических данных локально и на изолированном Windows runner: при закрытии его владельца система завершает зависший процесс; для канала проверены права текущего пользователя и идентификатор подключившегося процесса. Настоящий обработчик точки проверен при задержанном тестовом чтении с подменённой отрисовкой. Прототип ещё не подключён к источникам приложения, фактическое окно и переключение при обновлении источников не проверены. Независимая проверка выявила необходимость сохранить события между ответами и устранить окно запуска процесса до привязки к владельцу. Эксперимент macOS переносит чтение Codex с потока интерфейса, но Claude и другие источники пока остаются синхронными. Необходимы проверки первоначального и затянувшегося чтения, смены языка и каталога, восстановления источника и устаревших ответов.
- При нескольких помощниках текущие источники не дают достоверного времени именно отображённого действия для сравнения разных журналов; неподтверждённое или завершённое действие нельзя выдавать за выполняющееся. Пользователь выбрал счётчик всех запущенных помощников до подтверждения их выхода, в том числе при неизвестном состоянии.
- Решение пользователя: при наличии плана показывать число запущенных помощников в активном этапе; без плана или в паузе, пока активного этапа нет, — у названия задачи. Когда появится активный этап, переносить число в него. Текущие данные Windows и macOS подтверждают связь помощника с задачей, но не с конкретным этапом: число на активном этапе означает общее число связанных помощников, а не подтверждённое назначение каждого из них на этот шаг. Реализация и проверка ещё не завершены.
- Решение пользователя: уменьшать счётчик только после явного закрытия помощника. Завершение отдельного хода не доказывает закрытие. Надёжный сигнал закрытия и безопасное сохранение ранее подтверждённой связи при временной потере данных проверяются; если источник не сообщает о закрытии, число может оставаться устаревшим и не должно выдаваться за подтверждённо работающее.
- Для локального Codex изучается внутренний источник: в [схеме OpenAI](https://github.com/openai/codex/blob/main/codex-rs/state/migrations/0021_thread_spawn_edges.sql) есть таблица связей `thread_spawn_edges`. Согласно [реализации закрытия](https://github.com/openai/codex/blob/main/codex-rs/core/src/agent/control/legacy.rs), запись `closed` появляется до остановки помощника и не доказывает, что она прошла успешно; `open` не доказывает выполняющуюся работу. Временные сессии могут отсутствовать в таблице, а закрытие родителя нельзя автоматически распространять на все дочерние записи. Проверяются дополнительное подтверждение результата, совместимость версий, полнота и безопасное чтение; на macOS доступ к этой базе в текущем мониторе отсутствует.

Последующее решение пользователя о счётчике в этих исходниках ещё не реализовано. Изолированные проверки Windows включали программное переключение и визуальные состояния в светлой и тёмной темах; на macOS 15 и 26 прошли сборка тестов и 10 новых проверок выбора, а также синтетические превью. Окна установленных приложений, физическое нажатие и поведение во время заблокированного чтения не проверены. На Mac видимые отдельные помощники могут оставаться при отсутствии текущего подтверждения идентичности.
- macOS 0.3.11 при нескольких журналах одного чата не считает старый журнал единственным: ранее видимая карточка сохраняется неподтверждённой, а новая может не появиться. Нужен безопасный способ показать новые наблюдения без ложного подтверждения состояния или завершения.
- Решение пользователя: если состояние задачи Codex нельзя надёжно подтвердить, показывать карточку с пометкой «Статус не подтверждён», не объявляя работу успешно завершённой. Это уточнение заменяет ранее выбранное скрытие в рассматриваемом случае и не относится автоматически к поведению других источников.
