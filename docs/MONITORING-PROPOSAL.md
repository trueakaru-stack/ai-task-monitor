# Достоверность статусов и конфиденциальность

**Статус: согласованные функции в разработке.** Документ относится к Windows и macOS. Согласованные решения перечислены ниже; недоступные сигналы и платформенные различия указаны отдельно. Существующие карточки и внешний вид не предлагается менять без отдельного согласования.

## Цель и границы

В первую очередь устранить ложное отображение активных задач и различать отсутствие задач и невозможность получить данные. Затем добавить диагностический журнал, а после проверки доступных сигналов — предупреждение о возможном цикле для Codex. Проверка и расширение Claude Code зависят от реальной тестовой сессии. Claude Design остаётся условным до появления проверяемого источника и тестовой сессии. Токены, стоимость и Visual Diff отложены в `BACKLOG.md`.

Существующий план задачи сохраняется: до пяти видимых этапов, прокрутка внутри карточки и передача прокрутки основному списку на границах. Выполненные и ожидающие этапы отображаются как прежде. Диагностический журнал — не второй список этапов. Процент выполненных пунктов плана не означает точный процент всей работы. Если достоверной оценки нет, процент не показывается.

## Что было обнаружено до изменений

- В Windows `Thread-Running` возвращает сохранённое значение, если размер файла сессии не изменился, до повторной проверки срока его актуальности. Поэтому ранее активная задача может оставаться активной после устаревания записи. Проверка самой функции с синтетическими данными о файле старше двух часов и неизменившимся кэшем подтвердила возврат состояния «активно»; пользовательские файлы не изменялись.
- На Windows наличие индекса Codex само по себе показывается как подключение. При ошибке чтения источника результат местами превращается в пустой список. На macOS ошибка чтения индекса также превращается в пустой список. Это может скрыть отличие между «задач нет» и «данные не получены».
- Необязательное подключение Claude Code на обеих платформах сейчас сохраняет в собственном локальном журнале до 240 символов запроса. Начало запроса используется как название, а также может попасть в поле текущей активности. Локальный журнал содержит и другие данные, в том числе рабочий путь и названия этапов; сокращение текста не исключает секреты.
- На текущем Windows-профиле файл журнала Claude Code не найден. Содержимое пользовательских журналов при подготовке этого документа не просматривалось и не удалялось.
- Официальная документация Codex описывает чтение состояния чата и уведомления app-server, но возможность внешнему клиенту надёжно наблюдать уже работающие чаты приложения без изменения их состояния требует отдельной проверки. Прямое чтение локальных файлов не является гарантированно стабильным публичным интерфейсом.

## Состояние реализации

- Windows: различение недоступного источника и неопределённого статуса, отдельный диагностический журнал и предупреждение о возможном цикле для Codex и Claude Code реализованы в локальных исходниках. Для Claude предупреждение проверено на синтетических событиях, но не в реальной сессии Claude Code. Для журнала есть настройки, фильтр и подтверждение очистки. В журнале нет названий задач, запросов, команд и их выводов; идентификаторы псевдонимизированы. Подробности и ограничения — в `PRIVACY.md`.
- macOS: новые события Claude не включают запросы пользователя; состояние недоступного источника и ранее замеченной задачи учитывается отдельно. Локальный диагностический журнал и предупреждение о возможном цикле Codex и Claude Code реализованы в исходниках; предупреждение Claude проверено синтетическими событиями, но не реальной сессией. Для журнала доступны настройки хранения, фильтр и подтверждение очистки. Старые события Claude на обеих платформах сохраняются без изменений.
- Ожидание подтверждения нельзя достоверно определить по доступному наблюдаемому источнику; приложение не должно выдавать догадку за подтверждённое состояние. Предупреждение о цикле основано на структурированных завершениях команд и остаётся приблизительным.
- Блокировка Codex обозначает владельца записи чата, а не обязательно выполняющийся ответ. Если задача началась до запуска монитора и новых событий нет, согласовано скрывать её до нового события. Поэтому тихая задача временно может быть не видна. Одна блокировка не доказывает выполнение задачи. Старые события Claude Code без новых событий после запуска тоже не показываются как активная задача; при новом событии ранее записанные этапы могут быть восстановлены.
- Ранее существовавший предел в два часа теперь не удаляет замеченную во время работы монитора тихую задачу: она показывается со статусом «Статус не подтверждён». Новое событие возвращает актуальное состояние. На Windows это относится к Claude Code, на macOS — к обоим источникам. Сам предел не подтверждает завершение работы и не является доказательством цикла.
- Проверка интерфейса Windows по снимкам WPF выполнена для указанных в отчёте состояний. Клавиатура, экранный диктор и поведение окна при фактическом взаимодействии остаются непроверенными.

## Предлагаемое поведение источников

1. **Данные получены, задач нет.** Показывать существующее пустое состояние «Активных задач нет» только когда данные от подключённых и отслеживаемых источников действительно получены.
2. **Работа подтверждена.** Показывать задачу активной, если источник подтверждает выполнение. Не считать отсутствие свежих событий само по себе доказательством завершения: долгая операция может работать молча.
3. **Состояние не подтверждено.** Если достоверное состояние определить нельзя, не выдавать последнее известное состояние за текущее. Согласовано: показывать «Статус не подтверждён» только у задач, замеченных после запуска монитора, а не у всех найденных старых записей. Отдельно проверить возможные тайм-ауты на реальных событиях; не выбирать порог произвольно.
4. **Источник недоступен.** Различать отсутствие приложения или подключения, отсутствие прав, ошибку чтения и временную недоступность. Если один источник недоступен, нельзя уверенно говорить, что активных задач нет во всех источниках. Согласовано: показывать краткое сообщение в основном окне, над карточками, если другие задачи работают; в компактном окне — короткой строкой под задачей.
5. **Ожидание действия пользователя и завершение.** Показывать ожидание как таковое только при наличии подтверждающего события. Завершённую задачу не называть активной. Согласовано: задача, ожидающая подтверждения пользователя, видна в компактном окне как ожидающая, а не как активная.

Сообщения об ошибках должны быть понятны без цветовых сигналов и доступны средствам чтения экрана. Состояния интерфейса, их точное расположение и поведение при сочетании работающих и недоступных источников согласовываются до изменений UI.

## Предлагаемые правила данных

Новый диагностический журнал хранится локально, не передаётся разработчику и содержит минимум сведений: время, источник, тип и результат события, а также ограниченный локальный идентификатор сессии для разделения параллельных задач. Идентификаторы и названия инструментов тоже могут быть чувствительными; формат и допустимые значения нужно проверить, не записывать произвольные строки без проверки.

В диагностический журнал не включать текст запросов, команд, выводов, действий и этапов, названия задач или пути проектов. Согласовано: запрос Claude Code не сохранять; если название можно получить только из запроса, показывать нейтральное название. Выбранная политика должна применяться ко всем полям собственного журнала, включая дублирующее поле активности, а не только к полю `prompt`.

Согласовано: срок хранения диагностических событий — не более семи дней локально, размер — не более 10 МБ. В настройках можно выбрать от 1 до 7 дней и от 1 до 10 МБ и вручную очистить журнал с подтверждением. При превышении ограничений удаляются только самые старые записи этого нового журнала. Автоочистка выполняется при работающем приложении и при следующем запуске; фоновая служба не устанавливается. Журнал и его настройки хранятся в локальной папке данных приложения. Старый собственный журнал приложения для Claude Code не изменяется и не удаляется автоматически без отдельного решения пользователя. При удалении Windows-приложения настройки и журналы сохраняются.

Файлы чатов и историю Codex не изменять. Подключение Claude Code остаётся необязательным: оно меняет настройки hooks Claude Code и создаёт локальный журнал приложения, поэтому не описывается как полностью read-only интеграция. Сведения на экране и в политике конфиденциальности должны соответствовать фактическому поведению обеих платформ.

## Журнал и возможный цикл

Журнал содержит диагностические события, а не дубликаты списка этапов. События разных сессий нельзя смешивать; нужно учитывать неполные записи, повторения, перезапуск и ротацию источника. Согласовано: в настройках есть раздел «Журнал» с двумя компактными выпадающими списками для пределов хранения и действиями «Открыть журнал» и «Очистить». Подтверждение очистки показывается внутри окна. Общий журнал открывается в том же окне, показывает время и тип события и позволяет отфильтровать события по задаче. Набор типов событий и формат записи требуют технической проверки.

Предупреждение «Возможный цикл» объясняет основание и не останавливает работу. Согласованное начальное правило — пять последовательных завершений одной команды с одинаковым ненулевым кодом ошибки за десять минут. Порог настраивается от 3 до 10 повторов, интервал — от 1 до 30 минут. Другая команда, успешная команда или изменение файла сбрасывают счётчик. Предупреждение можно скрыть до следующей последовательности. Пользователь согласился, что намеренные повторы иногда могут вызвать ложное предупреждение. Для сравнения используются временные ключевые отпечатки в памяти; команды и выводы в журнал не записываются.

## Приёмка после согласования

- Несколько параллельных задач, завершение и длительная тихая операция не приводят к выдуманным статусам; отдельно проверяется устаревший кэш Windows.
- Пустой список, отключённый источник и ошибка доступа различаются; работающий источник продолжает отображаться при сбое другого.
- Текущий список этапов и его прокрутка не меняются. Если плана нет, этапы не выдумываются; проценты не создаются из недостаточных данных.
- Синтетические данные с секретами проверяются на отсутствие запрещённого содержимого во всех собственных сохраняемых полях. Политика удаления не затрагивает журналы самих Codex или Claude Code.
- Проверяются обработка частичных записей, повторений и ротации, ограничения ресурсов и разных сессий, настройки безопасности файлов, а также восстановление после перезапуска.
- Изменения интерфейса проверяются визуально в фактических приложениях, в светлой и тёмной темах, полном и компактном видах, с клавиатуры и средствами доступности. Непроверенные платформы и состояния отдельно обозначаются.
- Реальные интеграции Claude и нативная работа macOS не считаются проверенными только по синтетическим тестам или анализу исходников.
